# Fixes: core/unit

> Temporary record of fixes. Delete it when the pull request merges.

| File         | Problem                                                                                                                                                                                                                                                           | Fix                                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runtime.ts` | The kernel saved the persisted keys of a unit only in `destroy`. A tab that closed or crashed without `destroy` lost them: for example, the decisions of Consent. Found while designing Settings (M9), which keeps preferences the same way.                      | The runtime saves the persisted keys after they change (one save for the changes of one task, saves in order, a failed save reported), and still saves at destroy. A test in `test/kernel.spec.ts` checks it. |
| `kernel.ts`  | `stop` destroyed the subsystems in reverse dependency order, so the Notification Center could stop while the Queue still delivered a broadcast to it; the sender got `UnitUnavailableError` at every shutdown. Found by the example of `@webkrnl/platform` (M10). | `stop` is the mirror of `start`: featurized subsystems first, then it waits (at most 2 s) for `router.idle()`, then the centralized ones. `PacketRouter` has an optional `idle()`.                            |
