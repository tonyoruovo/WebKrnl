# Fixes: core

> Temporary record of fixes. Delete it when the pull request merges.

| File                                           | Problem                                                                                                                                                                                                                                                                                                                                                                                                | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scheduler.ts`                                 | In Node, the `message-channel` scheduler called `unref()` on its port one time, at creation. A task queued while nothing else kept the process alive never ran: Node exited first. A processor on the virtual host in a Node script did not finish. The `core/processor` example in `EXAMPLES.md` found it.                                                                                            | The port is referenced while tasks wait and released when the queue is empty. The `unref()` call now comes after `onmessage` is set, because setting `onmessage` references a Node port. A test in `test/processors.spec.ts` checks the order of the calls.                                                                                                                                                                                                                                                             |
| `host.ts`                                      | `VirtualHost.stop` ran the teardown of the processor at once, while calls that it had accepted still waited in the scheduler. Those calls then ran on a stopped processor. A write to Storage just before a reload was lost. Found by the M8 gate test (a Global envelope in the outbox, then an immediate reload).                                                                                    | `stop` waits for the accepted calls (`Promise.allSettled`), then runs the teardown. The Storage coordinator also waits for its own request queue in `teardown` (`packages/storage/src/FIXES.md`).                                                                                                                                                                                                                                                                                                                       |
| `signout.ts`                                   | `watchSignOut` read `views.state` of any unit with the target id. A unit with the id `auth` that is not Auth (the test double of the M3 flows test) has no state view, and the watch reported a `TypeError`. Found by the browser test run of M8.                                                                                                                                                      | `watchSignOut` ignores a unit without a state view, as it ignores a stopped Auth.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `runtime.ts`                                   | The kernel saved the persisted keys of a unit only in `destroy`. A tab that closed or crashed without `destroy` lost them: for example, the decisions of Consent. Found while designing Settings (M9), which keeps preferences the same way.                                                                                                                                                           | The runtime saves the persisted keys after they change (one save for the changes of one task, saves in order, a failed save reported), and still saves at destroy. A test in `test/kernel.spec.ts` checks it.                                                                                                                                                                                                                                                                                                           |
| `testing/index.ts`, `supervisor.ts`, `host.ts` | In a full browser test run (five browsers at the same time), the dev server sometimes took more than 5 s to transform a worker module the first time. The worker handshake timed out, and the runner moved the processor to the virtual host. Tests that expect a worker host failed: Storage (`host: 'virtual'` in Edge), and the hosts, Crypto and Realtime tests in Chrome. Each test passed alone. | The new runner option `handshakeTimeoutMs` (kernel option `processors.handshakeTimeoutMs`) sets the timeout for processors that do not set their own. The order is: the definition, then the option, then 5 s, so the production default does not change. `createTestPlatform` sets the option to `TEST_HANDSHAKE_TIMEOUT_MS` (30 s). A test that checks the `handshake-timeout` failover still sets a short timeout on its definition. Tests in `test/processors.spec.ts` check the order and the test platform value. |
| `kernel.ts`                                    | `stop` destroyed the subsystems in reverse dependency order, so the Notification Center could stop while the Queue still delivered a broadcast to it; the sender got `UnitUnavailableError` at every shutdown. Found by the example of `@webkrnl/platform` (M10).                                                                                                                                      | `stop` is the mirror of `start`: featurized subsystems first, then it waits (at most 2 s) for `router.idle()`, then the centralized ones. `PacketRouter` has an optional `idle()`.                                                                                                                                                                                                                                                                                                                                      |
